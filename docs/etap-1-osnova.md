# Этап 1. База данных и каркас

**Цель этапа: есть пустой сайт, который открывается по ссылке и умеет читать и писать данные в Supabase.**

---

## Что должно появиться

Файлы `index.html`, `styles.css`, `app.js`, папка `netlify/functions`. Подключение к Supabase через CDN. Таблицы в базе созданы, хранилище настроено.

Внешне на этом этапе достаточно белой страницы с надписью «СВАДЬБА · ripsigal & jimbei5» и служебной строкой, показывающей, что связь с базой есть.

---

## Данные от Энрике

URL проекта Supabase и публичный anon-ключ. Если их нет — запроси и не выдумывай.

Ключ anon по своей природе публичный, его можно держать прямо в `app.js`.

---

## Таблицы

**guests** — гости.

| Поле | Тип | Смысл |
| --- | --- | --- |
| id | uuid, ключ | |
| nick | text | как ввёл гость |
| nick_key | text, уникальное | ник в нижнем регистре, для проверки занятости |
| pin_hash | text | SHA-256 от пина |
| avatar_kind | text | `preset` или `custom` |
| avatar_value | text | номер заглушки или путь к файлу |
| banned | boolean | по умолчанию false |
| created_at | timestamptz | |

**photos** — фотографии.

| Поле | Тип | Смысл |
| --- | --- | --- |
| id | uuid, ключ | |
| guest_id | uuid | ссылка на guests |
| preview_path | text | путь в хранилище Supabase |
| yadisk_path | text | путь на Яндекс.Диске, может быть пустым |
| reports | int | число жалоб, по умолчанию 0 |
| hidden | boolean | скрыто ли фото |
| created_at | timestamptz | |

**likes** — лайки. Поля `photo_id` и `guest_id`, вместе составляют ключ, чтобы один гость не лайкнул дважды.

**comments** — комментарии. Поля `id`, `photo_id`, `guest_id`, `body`, `created_at`.

**settings** — настройки в виде пар ключ-значение. Начальные записи: `upload_enabled` со значением `true`, `window_start` и `window_end` с датами из памятки.

---

## Хранилище

Публичный бакет `photos` для превью и `avatars` для загруженных аватарок. Публичный — потому что лента должна открываться быстро и без токенов.

---

## Доступ к данным

Проект — боевой макет на один вечер, поэтому доступ настраиваем просто: анонимная роль может читать всё и вставлять записи, но не может удалять чужое и менять поле `banned`.

Удаление своих фото и комментариев делаем через проверку `guest_id` на стороне правил доступа.

---

## Что Claude проверяет сам

1. Страница открывается локально без ошибок в консоли.
2. Тестовая запись добавляется в `guests` и читается обратно.
3. Тестовый файл загружается в бакет `photos` и открывается по публичной ссылке.
4. Скриншот страницы приложен к отчёту.
