# Часть 1. Фаза 0 — подготовка

**Цель: к концу фазы 0 есть домен, база, хостинг и оплаченный Диск. Кода ещё нет.**

Делает Энрике. Занимает около часа. Порядок шагов важен.

### Шаг 1. Купить домен

Регистратор на выбор: reg.ru, timeweb, nic.ru. Домен `ripsigal-jimbei.ru`.

После оплаты зайти в личный кабинет и убедиться, что домен числится за тобой. Этого достаточно, чтобы верстать флаер, — работать в интернете он начнёт позже.

### Шаг 2. Создать проект Supabase

Supabase — это база данных и хранилище фотографий.

Идти на supabase.com → Start your project → вход через GitHub → New project. Регион выбрать ближайший к России из доступных.

Забрать две строки: Settings → API → `Project URL` и ключ `anon public`. Прислать их в чат.

### Шаг 3. Завести Netlify

Netlify — бесплатный хостинг, место, где лежит сайт.

Идти на netlify.com → Sign up → Continue with GitHub. Пароль придумывать не надо, вход через уже имеющийся GitHub.

Дальше ничего не настраивать, сайт создадим на первом этапе.

### Шаг 4. Завести Яндекс-аккаунт для фото

Отдельный аккаунт, не личный. Внутри — подписка на объём.

Важно про цены: тарифа «100 ГБ за 199 рублей» из старого ТЗ больше нет. Бесплатно дают 5 ГБ, а нужно около шести. Минимальный платный тариф сейчас на 200 ГБ, цена зависит от акций и срока оплаты — смотреть на месте.

Срок: **до обеда 4 августа**, потому что проверку Диска мы двигаем на утро.

### Шаг 5. Собрать тестовые фото

20–30 настоящих снимков с телефона в одну папку. Обязательно вперемешку вертикальные и горизонтальные, пара тяжёлых.

### Проверка фазы 0

Домен виден в кабинете регистратора. Две строки от Supabase присланы. Netlify открывается. Яндекс оплачен. Папка с фото готова.

# Часть 3. Принятые решения

## Панель владельца: без пароля, но с посредником

Экрана ввода пароля не будет. Вместо него секретный кусок прямо в ссылке: у кого ссылка — у того доступ.

Ссылка вида `ripsigal-jimbei.ru/panel#k=длинный-случайный-набор`. Сохранить в заметках и на главный экран айфона.

**Служебный файл-посредник на Netlify остаётся обязательно.** Причина: панель работает тем же публичным ключом, что лежит в открытую в коде сайта. Если разрешить базе принимать команды «забань» и «выключи приём» напрямую из браузера, их сможет отправить любой гость, даже не зная адрес панели. Спрятанная ссылка от этого не защищает, а посредник защищает.

Правила: не показывать никому экран с этой ссылкой, не открывать панель при гостях. При утечке секрет меняется в настройках Netlify за минуту.

Панель закрывается от поисковиков служебной пометкой и файлом robots.

## Пин-код: сверка внутри базы

Внутрь базы кладётся маленькая программа, которая принимает ник и пин, сама сверяет и отвечает «да» или «нет». Отпечатки пинов наружу не отдаются вообще.

Пятнадцать минут работы, новых файлов и ключей не требует.

Блокировка после неудачных попыток остаётся как в памятке: **3 попытки, затем пауза 60 секунд.** Она живёт в браузере и защищает от гостя, который тычет наугад.

## Размер превью: 150 КБ вместо 250 КБ

Расчёт трафика. Один гость за вечер просматривает около 150 снимков. Полторы сотни гостей на полторы сотни фото по 250 КБ дают 5,6 ГБ — а бесплатный потолок Supabase 5 ГБ в месяц. Вылетаем, и фото перестают открываться ближе к ночи.

При 150 КБ выходит 3,4 ГБ, запас около трети. На экране телефона разница не видна.

Меняется в этапе 4: длинная сторона до 1440 точек остаётся, качество снижаем, целевой размер 150 КБ, повтор с более грубым качеством при превышении 250 КБ.

## Страховка на платный тариф

Карта привязана к Supabase заранее. Если трафик всё-таки кончится посреди вечера, платный тариф включается одной кнопкой, код править не надо.

Признак, что пора: фото в ленте перестали открываться, а сайт при этом жив.

# Часть 4. Правки по этапам

**Этап 1.** Добавляется второй служебный файл на Netlify — посредник для панели. Добавляется секретный ключ базы в настройки Netlify. Добавляется программа сверки пина внутри базы.

Отдельно предупреждение для Claude Code: Supabase поменял правила для проектов, созданных после 30 мая 2026 года. Таблицы надо явно открывать для внешнего доступа отдельной командой, иначе сайт их не увидит, а ошибка будет выглядеть непонятно.

**Этап 2.** Проверка пина идёт через программу в базе, а не сверкой в браузере.

На экране регистрации появляется серая строка про согласие: загружая фото, гость соглашается, что их увидят все гости свадьбы.

Восстановления пина нет. Забыл — регистрируется под новым ником.

Шесть картинок для аватарок рисует Claude: кольца, сердце, цветок, бокал, голубь, торт. Чёрный контур на белом.

**Этап 4.** Целевой размер превью 150 КБ.

**Этап 6.** Экран пароля убирается, вход по секретной ссылке. Все команды панели идут через посредника.

**Этап 7.** Разведка вынесена вперёд, на утро 4 августа. Цены и объёмы Яндекса уточнены по факту.

**Этап 8а. Флаер.** Формат А6, 105 на 148 миллиметров. Односторонний, чёрно-белый. Количество Энрике определяет сам при сдаче. Плакаты формата А3 решено не делать.

**Этап 8б.** После 8 августа показываем страницу со словами о том, что фото у молодожёнов. Ссылок и альбомов не добавляем.

# Часть 5. Что решено не делать

Кнопки «скачать фото» у гостей не будет. Гости только смотрят.

Плакатов А3 не будет, только флаеры.

Запасного канала для фото на случай падения сайта не будет. **Последствие проговорено: если сайт ляжет в разгар вечера, фото за этот вечер не соберёт никто, второй попытки у свадьбы нет.** Решение принято сознательно.

# Часть 6. Осталось выяснить

**Интернет в зале.** Наличие вайфая и его качество неизвестны. Пока считаем, что связь средняя, — отсюда и сжатие до 150 КБ, и отправка фото по одному. Если выяснится, что связь плохая, снижаем ещё, это правка в одну строку.

**Ведущий.** Кодовое слово ему передаёт Энрике лично. Попросить произнести слово несколько раз за вечер, чтобы услышали и опоздавшие.
